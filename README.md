# VDF.BY

Интернет-магазин автосвета на Next.js. Каталог, корзина, заказ в Telegram,
админка на `/admin/`. Данные — SQLite в `var/shop.db`.

## Запуск

```bash
npm install --ignore-scripts   # см. примечание ниже
cp .env.example .env           # можно оставить пустым: без токена
                               # заказы просто не уйдут в Telegram
npm run dev                    # http://localhost:3000
```

При первом запуске `predev` сам создаст базу и зальёт в неё каталог из
`data/`. Фотографий в `media/` нет — вместо них будут заглушки, это нормально.

Завести администратора:

```bash
npm run admin -- --login admin      # пароль спросит скрытым вводом
```

## Подбор по автомобилю

Справочник марок, моделей и поколений (421 / 4880 / 9871) лежит в
`data/cars-catalog.json` и заливается в базу командой `npm run import-cars`.
Она идемпотентна: строки обновляются по внешнему id, адреса уже заведённых
записей не трогаются, привязки товаров не рвутся. `deploy/deploy.sh`
выполняет её на каждом деплое.

Товары привязываются к поколениям в карточке товара (`Подходит к
автомобилям`). Из этих привязок и строится всё остальное:

| Адрес | Что на нём |
|---|---|
| `/podbor/` | марки, к которым подходит хотя бы один товар |
| `/podbor/bmw/` | модели марки и весь ассортимент под неё |
| `/podbor/bmw/3-serii/` | поколения с фотографиями |
| `/podbor/bmw/3-serii/v-e90-e91-e92-e93/` | товары под конкретное поколение |

Страницы создаются **только под существующие привязки**. Машина без
товаров своей страницы не получает и в `sitemap.xml` не попадает: пустые
страницы в индексе не ранжируются сами и тянут вниз соседние.

Логотипы марок выкачиваются пачкой (`--logos`, ~420 файлов по паре
килобайт): в списке марку находят глазами, по значку. Фотографии поколений
— по требованию, в момент первой привязки: их девять тысяч, а нужны
единицы. И то и другое ложится в `public/img` через тот же конвейер, что и
фото товаров.
Ссылаться на чужой домен нельзя: политика безопасности сайта разрешает
картинки только со своего (`img-src 'self'`), да и чужой адрес может
перестать отвечать в любой день. Источник справочника — открытый
автокаталог; если понадобится заменить картинки на свои, менять придётся
только `photo_src` и `logo_src` в базе.

## Поиск и товарные площадки

Что сайт отдаёт роботам, помимо страниц:

| Адрес | Кому |
|---|---|
| `/sitemap.xml` | карта сайта с настоящими датами правки и фотографиями товаров |
| `/robots.txt` | правила обхода, ссылка на карту |
| `/feed.xml` | фид для Google Merchant Center (бесплатные карточки в Google Покупках) |
| `/yml.xml` | фид в формате YML — Яндекс, Onliner, Kufar |
| `/indexnow-key.txt` | подтверждение ключа IndexNow, если задан `INDEXNOW_KEY` |

Фиды собираются из каталога сами и пересобираются при сохранении товара.
Добавлять их в Merchant Center и на площадки нужно один раз — дальше они
ходят за ними по расписанию.

В разметке каждой страницы товара лежит предложение на **каждую комбинацию
опций**: своя цена, свой артикул, свой адрес (`?socket=h7`) плюс условия
доставки и возврата. Условия берутся из настроек магазина — сроки доставки
по каждому способу и окно возврата в днях. Числа там обязаны совпадать с
тем, что написано на странице «Доставка и оплата»: расхождение разметки и
текста — повод для ручных санкций, а не мелкая неточность.

## Где что

```
data/        каталог в JSON — источник для npm run import (формат: data/SCHEMA.md)
             плюс cars-catalog.json — справочник машин для npm run import-cars
media/       исходные фотографии (media/README.md)
src/app/     (shop) — витрина, admin — панель
src/lib/     каталог, база, авторизация, заказы, картинки
scripts/     импорт, администратор, бэкап, проверки
deploy/      nginx, systemd, deploy.sh
var/         база и бэкапы (не в репозитории)
```

## Про `--ignore-scripts`

`better-sqlite3` кладёт готовые бинарники прямо в пакет, но npm об этом не
знает и пытается собрать его из исходников — на Windows без Visual Studio
установка на этом падает. Флаг отключает лишнюю сборку; во всём дереве
зависимостей install-скрипт всего один, и он не нужен.

## Деплой

С рабочей машины, одной командой:

```bash
npm run deploy
```

Заходит по SSH на сервер и просит его забрать изменения из git и
пересобраться. Перед выкаткой проверяет, что всё закоммичено и запушено, —
сервер тянет код из репозитория, и незакоммиченная правка на сайт не
попадёт. Если сборка упадёт, сайт останется на прежней версии: перезапуск
идёт только после успешной сборки.

Та же команда работает и на самом сервере — из папки приложения она
выполнит деплой напрямую, без SSH. Либо, если привычнее, `./deploy/deploy.sh`.

Сайт запущен под PM2 как приложение `vdf` на порту 3011 (3000 и 3010
на сервере заняты другими проектами), nginx перед ним обратный прокси.
Node — 22 из nvm: системному 18, а `better-sqlite3` требует 22.

Подробности в шапках `ecosystem.config.cjs`, `deploy/nginx.conf` и
`deploy/deploy.sh`.
