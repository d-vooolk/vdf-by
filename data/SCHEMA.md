# Формат файлов каталога

Всё содержимое магазина лежит в этой папке. Правится руками, в обычном
редакторе. После правки — `npm run build` и деплой.

Проверка встроена в сборку: если ошибётесь в названии поля или забудете
запятую, `npm run build` упадёт и напишет, **какой файл и какое поле**
не сходятся. Сломанный сайт из этого получиться не может.

```
data/
  site.json          телефон, адрес, доставка, тексты «о магазине»
  categories.json    разделы каталога
  products/
    lamps.json       товары раздела «Лампы»
    lenses.json      товары раздела «Линзы»
    ...              любой новый файл подхватится сам
```

Файлы в `products/` можно называть как удобно и добавлять новые — код
менять не нужно. Раздел товара определяется полем `categoryId`, а не именем
файла. Разбивка на файлы нужна только вам: искать товар в файле на 60
позиций реально, в файле на 600 — нет.

## Товар

Обязательные поля выделены **жирным**.

| Поле | Тип | Что это |
|---|---|---|
| **`id`** | строка | Внутренний идентификатор. Латиница, цифры, дефис. Должен быть уникальным во всём каталоге. Менять после запуска не стоит — он входит в ключ корзины. |
| **`slug`** | строка | Адрес страницы: `slug: "osram-nb-200"` → `/product/osram-nb-200/`. Только латиница, цифры и дефис. **Менять после индексации нельзя** — старый адрес отдаст 404 и позиции в поиске потеряются. |
| **`categoryId`** | строка | `id` раздела из `categories.json`. Если такого раздела нет, сборка упадёт. |
| **`title`** | строка | Название. Показывается в каталоге, на странице, в поиске и в заголовке вкладки. |
| **`price`** | число | Базовая цена. Если у товара есть опции со своими ценами, эта используется как запасная. |
| `brand` | строка | Бренд. Попадает в фильтр каталога и в разметку для Google. |
| `oldPrice` | число | Старая цена. Показывается зачёркнутой, рядом считается процент скидки. Если она не выше текущей — просто не выводится. |
| `inStock` | да/нет | По умолчанию `true`. `false` убирает кнопку заказа. |
| `stockQty` | целое число | Складской остаток для внутреннего учёта. На витрину не попадает вообще: ни в текст страницы, ни в её исходный код. Поля нет — учёт по этому товару не ведётся, и это не то же самое, что `0`. |
| `costPrice` | число | Себестоимость — по чём товар закуплен. На витрину не попадает никогда: ни в текст страницы, ни в её исходный код, ни в фиды. В карточке товара рядом с ценой продажи по ней считаются прибыль, маржа и наценка. У товара с опциями считается от базовой цены. |
| `storageCode` | строка | Складской номер — где позиция лежит на складе. Тоже внутреннее: видно в карточке товара и в строке списка товаров в админке, на сайте — нигде. |
| `badge` | строка | Плашка на карточке: «Хит», «Новинка», «Распродажа». |
| `featured` | да/нет | `true` — товар попадает в блок «Выбирают чаще всего» на главной. |
| `unit` | строка | Единица: `"комплект"`, `"шт."` — в админке выбирается из списка. Выводится как «цена за …». |
| `sku` | строка | Артикул: шесть цифр, у каждого товара свои. Админка подставляет его сама при создании товара и умеет перегенерировать по кнопке; два товара с одним артикулом сохранить нельзя. |
| `images` | список строк | Общая галерея. Пути относительно папки `media/` (см. ниже). |
| `videos` | список | Видео товара: `[{ "src": "lenses/hella/obzor.mp4", "poster": "lenses/hella/obzor.jpg", "w": 1920, "h": 1080 }]`. Файлы лежат в `public/video/`, загружаются из админки (любой формат, в том числе mov с айфона, до 500 МБ). Сервер перекодирует ролик через ffmpeg в mp4 (H.264, не больше 1920 px по длинной стороне, HDR приводится к обычному диапазону) и вырезает обложку из первой секунды. На странице товара видео встаёт в галерею после фото. |
| `description` | строка | Описание товара. Пустая строка (`\n\n`) разбивает текст на абзацы. Текст целиком попадает и в HTML страницы (то есть в индекс Google), и в поиск по сайту. **Первый абзац вдобавок особенный**: из него собирается описание страницы для поисковой выдачи, поэтому начинать стоит с одной-двух фраз о главном. |
| `specs` | список | Таблица характеристик: `[{ "name": "Мощность", "value": "55 Вт" }]`. |
| `optionGroups` | список | Опции товара — цоколь, сторона, цвет. Разбор ниже. |
| `seoTitle` | строка | Заголовок для поиска, если стандартный не устраивает. По умолчанию — название + цена. |
| `seoDescription` | строка | Описание для поиска. По умолчанию — первый абзац `description`. |
| `_comment` | строка | Заметка для себя. Разрешена в любом объекте, на сайт не попадает. |

Полей `excerpt` и `tags` у товара больше нет. Короткое описание слилось с
полным в одно `description` — первым абзацем, — а поисковые слова убраны
совсем. Товары в базе перевела миграция №5, руками ничего делать не нужно.
Ищут теперь по названию, бренду, разделу, всему тексту описания,
характеристикам и подписям опций.

Чего в этом файле нет: **привязки товара к автомобилям**. Они живут в
отдельной таблице базы (связь многие-ко-многим: одна лампа встаёт в десяток
машин), правятся в карточке товара и в JSON не выгружаются. Подробности —
в README, раздел «Подбор по автомобилю».

## Опции: цоколь H7 / HB4 / H11 со своими фотографиями

Это то, ради чего формат сложнее обычного. Пример:

```json
"optionGroups": [
  {
    "id": "socket",
    "name": "Цоколь",
    "hint": "Цоколь указан на старой лампе",
    "values": [
      {
        "id": "h7",
        "label": "H7",
        "price": 84.9,
        "images": ["lamps/osram/h7-1.jpg", "lamps/osram/h7-2.jpg"]
      },
      {
        "id": "h11",
        "label": "H11",
        "price": 92.5
      },
      {
        "id": "hb4",
        "label": "HB4",
        "price": 96,
        "inStock": false,
        "images": ["lamps/osram/hb4-1.jpg"]
      }
    ]
  }
]
```

Что получится на странице:

- **H7** — своя галерея из двух фото, цена 84,90 р.
- **H11** — фотографий нет, поэтому показывается общая галерея из `images`
  товара. Цена 92,50 р.
- **HB4** — своя галерея, но кнопка заказа выключена: `inStock: false`.

### Три правила, по которым всё считается

**Фотографии.** Берутся у первого — в том порядке, в котором наборы
перечислены в `optionGroups` — выбранного значения, у которого заполнено
`images`. Если ни у одного выбранного значения своих фото нет, показывается
общая галерея товара.

**Цена.** Берётся `price` первого выбранного значения, где это поле задано.
Если не задано нигде — цена товара. Затем прибавляются **все** `priceDelta`
выбранных значений.

**Наличие.** Товар доступен, если сам он `inStock` и ни у одного выбранного
значения не стоит `inStock: false`.

### Поля значения опции

| Поле | Что делает |
|---|---|
| **`id`** | Идентификатор внутри набора. Латиница, цифры, дефис. |
| **`label`** | Что видит покупатель: `"H7"`, `"5000K — белый"`, `"Левое"`. |
| `price` | Абсолютная цена — перебивает цену товара. |
| `priceDelta` | Надбавка к цене. Складывается со всеми остальными надбавками. |
| `images` | Своя галерея. Нет поля — покажется общая. |
| `inStock` | `false` выключает этот вариант. |
| `sku` | Артикул конкретного варианта. |

### Несколько наборов опций

Наборов может быть сколько нужно — например «Цоколь» и «Цветовая
температура». Тогда цена складывается: абсолютная из первого набора плюс
надбавки из остальных.

```json
"price": 65,
"optionGroups": [
  { "id": "socket", "name": "Цоколь", "values": [
      { "id": "h7", "label": "H7", "price": 65 },
      { "id": "h4", "label": "H4", "price": 75 }
  ]},
  { "id": "temp", "name": "Температура", "values": [
      { "id": "5000k", "label": "5000K", "priceDelta": 0 },
      { "id": "6000k", "label": "6000K", "priceDelta": 5 }
  ]}
]
```

H4 + 6000K = 75 + 5 = **80 р.**

Практический совет: цены задавайте абсолютным `price` в **первом** наборе, а
в остальных — только надбавками `priceDelta`. Так глазами по файлу считать
проще всего.

## Фотографии

Складывайте как есть в папку `media/`, структуру придумывайте любую. В JSON
пишется путь **относительно `media/`**:

```
media/lamps/osram-nb200/h7-1.jpg   →   "lamps/osram-nb200/h7-1.jpg"
```

Ничего сжимать и переименовывать заранее не нужно. На сборке
`scripts/images.mjs` сам сделает из каждого снимка версии в AVIF и WebP на
несколько ширин, посчитает размытую заглушку и сложит результат в
`public/img/`. Повторная сборка трогает только новые файлы.

Снимки с телефона можно кидать как есть — поворот из EXIF учитывается,
на боку фото не лягут.

**Если фото нет** — не страшно: на его месте появится аккуратная заглушка, а
сборка выведет список недостающих файлов. Сайт при этом собирается и
работает.

## Раздел каталога

```json
{
  "id": "lamps",
  "slug": "lampy",
  "name": "Лампы",
  "order": 3,
  "excerpt": "Галоген, ксенон и LED во всех популярных цоколях.",
  "description": "Длинный текст под сеткой товаров.\n\nВторой абзац.",
  "seoTitle": "Автомобильные лампы купить в Минске — H7, H11, HB4",
  "seoDescription": "Описание для поисковой выдачи, до 165 символов.",
  "image": "categories/lamps.jpg"
}
```

`order` задаёт порядок в меню и на главной. `menuName` можно указать, если в
меню название должно быть короче, чем на странице раздела.

### Подразделы

Раздел можно вложить в другой — полем `parentId`:

```json
{
  "id": "angel-eyes",
  "slug": "angelskie-glazki",
  "parentId": "accessories",
  "name": "Ангельские глазки",
  "order": 20
}
```

Адрес такого раздела вложенный: `/catalog/aksessuary/angelskie-glazki/`.

Два правила, и оба проверяются при сохранении:

- **Уровня ровно два.** Подраздел подраздела не бывает: третий уровень не
  влезает ни в хлебные крошки, ни в меню на телефоне.
- **Товары лежат только в разделах без подразделов.** Как только у раздела
  появляется первый подраздел, его собственная страница показывает плитку
  подразделов, и товару там не показаться. Поэтому сначала переносим товары
  в подразделы, потом создаём подразделы — или наоборот, но не вперемешку.

При удалении раздела его подразделы поднимаются на верхний уровень вместе со
своими товарами, а их адреса укорачиваются.

### Подбор по автомобилю

Раздел можно связать с автомобилями — полем `carFitment`:

```json
{
  "id": "glasses",
  "slug": "stekla-far",
  "name": "Стёкла фар",
  "carFitment": true
}
```

Что это включает:

- в карточке каждого товара этого раздела появляется блок «Подходит к
  автомобилям» — выбор марки, модели и поколения;
- у раздела появляются вложенные страницы подбора:
  `/catalog/stekla-far/bmw/`, `/catalog/stekla-far/bmw/3-seriya/`,
  `/catalog/stekla-far/bmw/3-seriya/e90/`;
- на странице самого раздела над сеткой товаров встают иконки марок.

Раздел без этого поля работает как раньше: ни поля привязки в товарах, ни
вложенных адресов у него нет.

Ограничение одно, и оно проверяется при сохранении: **только раздел
верхнего уровня без подразделов**. Второй сегмент адреса не может быть
одновременно подразделом и маркой машины, а у подраздела страницы подбора
уехали бы на пятый уровень вложенности, куда поиск почти не заходит.

Привязки товаров хранятся отдельной таблицей и снятие галочки их не
удаляет: машины просто пропадают с витрины и из формы. Вернули галочку —
вернулись и они.

Подробнее про структуру адресов и решения по SEO — `docs/car-fitment.md`.

## Как добавить товар: короткий чек-лист

1. Открыть нужный файл в `data/products/` (или создать новый).
2. Скопировать похожий товар целиком, вставить рядом.
3. Поменять `id`, `slug`, `title`, `price` — они должны быть уникальны.
4. Положить фото в `media/…`, прописать пути в `images`.
5. `npm run build` — если что-то не сходится, сборка скажет что именно.
6. Задеплоить.

## Что нельзя менять после запуска

- **`slug` товара и раздела.** Это адрес страницы. Google его уже
  проиндексировал; смена адреса = потеря позиций и 404 по старым ссылкам.
- **`id` товара и `id` значений опций.** Они входят в ключ позиции в
  корзине. У покупателей, у которых товар уже лежит в корзине, он «потеряет»
  цену и подтянет её заново из прайса.

Всё остальное — цены, названия, описания, фото, наличие — правится свободно.
