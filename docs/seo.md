# SEO-сводка

Админка → «Сводка» → «SEO» (`/admin/seo/`).

## Откуда данные

| Источник | Что берём | Доступ |
|---|---|---|
| Google Search Console | клики, показы, CTR, позиции по запросам и страницам, по дням, sitemap | сервисный аккаунт, ключ `var/gsc-key.json`, ресурс `sc-domain:vdf.by`, права «Ограниченные» |
| Яндекс.Вебмастер | ИКС, страниц в поиске, диагностика, sitemap, популярные запросы, исключённые страницы | OAuth-токен `var/yandex-token.txt`, хост `https:vdf.by:443` (главное зеркало) |
| Яндекс.Метрика | источники, поисковые системы, входные страницы, цели, визиты по дням | тот же токен, права `metrika:read`, счётчик 112885899 |
| Сайты конкурентов | sitemap (размер, свежесть), главная (title, h1, разметка), ответ сервера, PageSpeed | открытые данные, без ключей |

Ключи лежат в `var/` на сервере, в git не попадают. Токен Яндекса живёт
около года — когда истечёт, сводка покажет ошибку 401, токен получают
заново тем же способом и кладут в тот же файл.

PageSpeed без ключа Google ограничивает по частоте. Если в таблице
конкурентов скорость пустая, задайте `PAGESPEED_API_KEY` в `.env`
(Google Cloud → APIs & Services → PageSpeed Insights API → ключ).

## Когда обновляется

`deploy/deploy.sh` пишет `/etc/cron.d/vdf-seo`:

- поиск и Метрика — каждый день в 6:20, `POST /api/cron/seo/?kind=search`;
- конкуренты — по понедельникам в 5:00, `POST /api/cron/seo/?kind=competitors`.

Кнопки «Обновить сейчас» и «Проверить конкурентов» запускают то же самое.
Снимки хранятся в таблице `seo_snapshots`: последних 120 по поиску и 60 по
конкурентам. Список конкурентов правится на той же странице.

Позиции сравниваются так: средняя позиция за последние 28 дней против 28
дней до них. У Google период сдвинут на 3 дня — Search Console отдаёт
данные с задержкой.

## Ключевые фразы и Topvisor

Вкладка «SEO → Ключевые фразы» (`/admin/seo/keywords/`). Список лежит в
файле `var/seo-keywords.json` на сервере: группы фраз, у каждой целевая
страница, приоритет, тип запроса и пояснение. У отдельной фразы может быть
своя страница — в редакторе это пишется как «фраза | /адрес/». «Скачать CSV
для Topvisor» отдаёт столбцы «Запрос; Группа; Целевая страница» — их
Topvisor принимает при импорте запросов из файла.

Рядом с каждой фразой — последние позиции из проекта Topvisor для vdf.by
по всем его регионам и отметка, отслеживается ли фраза. ⚑ — в выдаче стоит
не та страница, что задана целевой. Доступ — `var/topvisor.txt` (User ID и
API-ключ, по строке). Данные Topvisor кэшируются на 10 минут. Сайт только
читает Topvisor: запросы в проект не добавляет и проверки позиций не
запускает — они платные.

## Подборки в разделах

У раздела верхнего уровня могут быть подборки — отдельные страницы под
частые запросы: `/catalog/bi-led-moduli/linzy-3-0/`, `/catalog/bi-led-moduli/aozoom/`.
Задаются в админке в карточке раздела, блок «Подборки»: заголовок (H1),
подпись на кнопке, адрес, слова для отбора, тексты и SEO-поля. Товар
попадает в подборку, если хоть одно слово есть в его названии, бренде или
характеристиках; «3.0», «3,0» и «3″» сравниваются одинаково. Ссылки на
подборки стоят над товарами раздела, сами подборки — в sitemap. На
подразделах подборок нет: адрес вышел бы третьего уровня.

## Услуги и мастерская

Отдельных страниц услуг на vdf.by нет намеренно: услуги продвигает сайт
мастерской prime-auto.by. У сайтов общий адрес и телефон, и две похожие
страницы по одному запросу Яндекс может счесть аффилированными и показать
только одну. На /ustanovka/ — короткое описание работ со ссылками на
страницы мастерской и ориентировочные цены. Цены взяты из прайса
prime-auto.by/price и записаны в `PRICES` в
`src/app/(shop)/ustanovka/page.tsx` — при изменении прайса их нужно
обновить там же.

## Даты в sitemap

Дата страницы — время её последней правки в админке. Ночной пересчёт цен
по курсу дату не трогает: иначе каждую ночь больше тысячи страниц
объявлялись изменёнными, и поисковики переставали доверять датам.

## Отчёт в Markdown

```
node scripts/seo-report.mjs
```

На сервере — `docker compose run --rm tools node scripts/seo-report.mjs`. Пишет `var/seo/report-ДАТА.md` и
`var/seo/raw-ДАТА.json` — удобно для подробного разбора.

`--raw var/seo/raw-ДАТА.json` пересобирает отчёт из сохранённых данных,
без запросов к Google и Яндексу.

В отчёте по Google: итоги за 28 дней и за последнюю неделю, сводка по
разделам сайта (сумма по страницам, карточки стёкол, рамок и световодов —
отдельными строками), запросы по показам. Google раскрывает запросы только
для части показов — сколько именно, написано над таблицей запросов; когда
доля маленькая, выводы делают по разделам и страницам.

## Перелинковка «для этой машины»

На карточке товара из раздела с подбором по авто — блок «Что ещё есть для
этой машины»: для каждого поколения из «Подходит к автомобилям» (до
четырёх) ссылки на страницы других разделов того же поколения — «Стёкла
фар для BMW X5 II (E70)», «Световоды для …», «Переходные рамки для …» — и
ссылка на свой раздел целиком («Все стёкла фар»). Считается в
`sectionsForProductCars` (`src/lib/car-branch.ts`). В «Товарах для этого же
авто» товары разных разделов идут вперемешку, чтобы десять мест не занимал
один раздел.

У переходных рамок одна и та же рамка (тип из `frame_type_products`,
например 110V) заведена отдельной карточкой под каждую машину. В блоке
«Подходит к автомобилям» сначала машины самой карточки, ниже — «Эта же
рамка (тип …) подходит и к другим машинам»: все поколения остальных
карточек этого типа, по маркам, со ссылками на подбор рамок поколения
(`getFrameTypeCars` в `src/lib/cars.ts`).

## Линзы для рамки

На карточках переходных рамок и в разделах марки, модели и поколения рамок —
блок «Линзы для этой рамки» / «Би-LED линзы для …»: четыре самые
просматриваемые линзы нужного размера из наличия и ссылки на подборку
размера и раздел би-LED (`src/lib/frame-lenses.ts`). Размер — по названию
рамки: по умолчанию 3.0″ (крепление Hella 3R), «2.5» в названии — 2.5″.
Рамки только под наборные матричные модули и кронштейны ПТФ остаются без
карточек линз: таких модулей в каталоге нет. Блок нужен и покупателю (линза
в комплект рамки не входит), и поиску — это ссылки на би-LED с сотен
страниц рамок, которые Google уже показывает.

## Чего здесь нет

Позиций конкурентов по запросам: Search Console и Вебмастер показывают
только свой сайт. Для этого нужен сервис проверки выдачи (Topvisor,
Yandex Search API) — подключается отдельным блоком.

## Пагинация

Страницы `?page=2` и дальше не спорят с первой за запрос: заголовок у них
«Раздел — страница N» без «купить в Минске» и без `seoTitle`, описание —
номер страницы и диапазон позиций (`laterPageMeta` в `src/lib/listing.ts`).
Текст раздела, FAQ и фото мастерской выводятся только на первой странице.
Яндексу в robots.txt отдан `Clean-param: page` — он склеивает пагинацию с
первой страницей, товары находит по sitemap. Google видит страницы как есть,
canonical у каждой свой.

## H1 раздела

Поле «Заголовок H1 на странице раздела» (`heading`) меняет заголовок только
на странице самого раздела. Название раздела (`name`) входит в заголовки
тысяч страниц подбора («Переходные рамки для BMW X5»), поэтому
формулировку под запрос — «Переходные рамки для линз» — ставят в `heading`,
а не в название.

## Фото мастерской

На странице раздела и на карточках товаров, у которых есть ссылка на услугу
мастерской (`src/lib/workshop-links.ts`), выводится блок фото работ Prime
Auto. Набор хранится в настройке `workshop_photos` — по виду работ:
заголовок, вводный текст и список фото с подписями. Фото лежат в
манифесте под `workshop/<вид>/` и, раз упомянуты в настройках, не попадают
в «неиспользуемые». Сейчас заданы наборы для стёкол фар (`glass`), для
световодов (`ledRepair`, фото под `workshop/led/`, ссылка на «Ремонт LED-фар
и ДХО» Prime Auto) и для би-LED (`biled`, `workshop/biled/` — показывается
у переходных рамок, би-LED модулей и линз); исходники — в библиотеке мастерской на сервере
(`/var/www/prime-auto/var/uploads/library`). Библиотека не смонтирована в
контейнер: нужные файлы кладут во временную папку в `var/` и передают
скрипту через `--library`.

## Цели Метрики и GA

| Цель | Когда |
|---|---|
| `order` | заказ из корзины или «в один клик» |
| `fit_check` | клик по мессенджеру в блоке «Подойдёт ли на вашу машину?» — товары разделов с подбором по авто |
| `product_messenger` | клик по мессенджеру «Спросить о товаре» на остальных товарах |

В Метрике цели `order`, `fit_check` и `product_messenger` нужно один раз завести как
«JavaScript-событие» с тем же идентификатором — иначе события приходят, но
в отчётах по целям не видны. Токен из `var/yandex-token.txt` только на чтение — через API цели не создаются (403), заводятся руками в интерфейсе.

## Сброс кеша страниц после правок в обход админки

`POST /api/cron/revalidate/` с заголовком `x-cron-key` (ключ из
`var/cron-key`) сбрасывает снимок каталога в памяти и ISR-кеш всех страниц.
Нужен скриптам, которые пишут в базу напрямую, — например
`scripts/seo-content-2026-10.mjs`.

## Тексты разделов скриптом

`node scripts/seo-section-content.mjs --content scripts/seo-….json` —
поля раздела (`set`), точечные замены в описании, ответы и новые вопросы
FAQ, наборы фото мастерской и перенос фото из библиотеки (`--library`).
Без `--apply` только проверяет и показывает, что изменится; с `--apply`
делает копию базы, пишет и сбрасывает кеш страниц. Повторный запуск того
же файла ничего не меняет. `carTextsFile` — тексты моделей из `.md`
(раздел `## марка/модель`, дальше абзацы); уже заданный другой текст
не перезаписывается без `--overwrite-texts`. Файлы: `seo-svetovody-2026-10.json`,
`seo-ramki-2026-10.json`, `seo-ramki-models-2026-10.json`,
`seo-biled-2026-10.json`. Поля подборок раздела правятся блоком
`category.collections` — `{ "слаг подборки": { поле: значение } }`.

## Точечные правки товаров и статей скриптом

`node scripts/seo-content-patch.mjs --content scripts/seo-….json` — у
товаров поля (`set`: `title`, `seoTitle` и т. д.), замены в описании
(`replaceInDescription`) и в ответах FAQ (`replaceInFaq`), характеристики (`specs`: `{ "Гарантия": "2 недели" }` —
заменяет значение или добавляет строку) и привязки к поколениям (`cars.remove` / `cars.add`
путями `марка/модель/поколение`); у статей — `title`, `seoTitle`,
`seoDescription`, `excerpt`. Без `--apply` только показывает изменения, с
`--apply` делает копию базы, пишет и сбрасывает кеш страниц. Повторный
запуск того же файла ничего не меняет. Файлы: `seo-2026-10-26.json`,
`seo-stekla-cards-2026-10.json`, `seo-stekla-faq-2026-10.json`.
